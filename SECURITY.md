# Security Policy

## Reporting a Vulnerability

Please report suspected security vulnerabilities privately to the security contact configured by OpenForge-Labs:

`[OpenForge-Labs: configure a private security reporting address or GitHub Security Advisories before publication]`

Do **not** create a public GitHub issue for a vulnerability. Public reports can expose users before a fix is available.

When reporting, include a clear description, affected files or components, reproduction steps, potential impact, and any suggested mitigation. Do not include real credentials, tokens, personal data, or other secrets in the report.

The OpenForge-Labs maintainers will acknowledge valid reports, investigate them privately, and coordinate disclosure after a fix or mitigation is available.

## Supported Versions

Security fixes are applied to the current maintained version of GigLedger. If you are using an older revision, update to the latest available version before reporting an issue that may already be fixed.
